# Reel bot: рилсы из Instagram Direct в карточке Битрикс24

Клиент присылает в Директ рилс или пост. Родной канал Instagram в Битрикс24 продолжает работать как раньше, а этот бот стоит рядом и делает три вещи:

1. Сохраняет ролик на вашем сервере и даёт постоянную ссылку на него.
2. Режет ролик на кадры и просит Claude написать бриф: что за товар и что уточнить у клиента.
3. Кладёт ссылку, кадры, сам ролик и бриф в ленту лида или контакта в Битрикс24. Если карточку найти не удалось, пишет в общий чат менеджеров.

```
Instagram → Meta → бот (сохранить, нарезать, бриф) → Битрикс24: лента карточки и чат менеджеров
```

## Что проверено, а что нет

Проверено автотестами и локальным запуском на поддельных серверах:

* приём и проверка подписи вебхука, защита от повторной доставки;
* скачивание ролика, нарезка на 8 кадров, выдача ролика по ссылке;
* формат запроса к Claude и разбор ответа;
* запись комментария с файлами в ленту, запасной путь в чат;
* сборка и запуск образа Docker.

Не проверено, потому что нужны ваши настоящие доступы:

* получает ли бот событие о рилсе одновременно с каналом Битрикс24;
* приходят ли события от людей без роли в приложении Meta до прохождения App Review;
* совпадает ли ID клиента у бота и в Битрикс24, то есть находится ли карточка автоматически;
* настоящий ответ Claude, настоящий Битрикс24 и запрос имени клиента в Instagram.

На эти вопросы отвечает шаг 6.

## Что понадобится

* Сервер с Docker и открытыми портами 80 и 443.
* Поддомен, например `reels.вашдомен.kz`, с записью A на адрес сервера.
* Облачный Битрикс24 на тарифе, где доступны входящие вебхуки.
* Профессиональный аккаунт Instagram и аккаунт разработчика Meta.
* Ключ API Claude (console.anthropic.com).

## Шаг 1. Вебхук Битрикс24

1. В Битрикс24 откройте «Разработчикам», затем «Другое», затем «Входящий вебхук».
2. Отметьте права `crm` и `im`.
3. Сохраните и скопируйте адрес вида `https://ВАШ.bitrix24.kz/rest/1/xxxxxxxx/`.
4. Создайте групповой чат для менеджеров. Его номер виден в адресе чата, в настройки он пишется как `chat123`.

Этот адрес равен паролю. Не отправляйте его в переписку и не публикуйте.

## Шаг 2. Запуск на сервере

```bash
git clone -b ccr-5261ace5-l4aasz --depth 1 https://github.com/Timemandroid/bitchat.git
cd bitchat/reel-bot
cp .env.example .env
nano .env          # заполните DOMAIN, PUBLIC_BASE_URL, ключи и адрес вебхука
docker compose up -d --build
docker compose logs -f app
```

`META_VERIFY_TOKEN` придумайте сами: любая длинная случайная строка, например вывод команды `openssl rand -hex 24`.

`META_APP_SECRET` и `IG_ACCESS_TOKEN` появятся на шаге 4. Пока впишите в `META_APP_SECRET` любую временную строку, иначе бот отклонит тестовое событие из шага 3.

Проверка: адрес `https://ВАШ_ДОМЕН/healthz` должен вернуть `{"ok":true}`.

## Шаг 3. Проверка без Meta

Этот шаг проверяет связку с Claude и Битрикс24, пока приложение Meta ещё не готово. Нужна прямая ссылка на любой видеофайл mp4 по HTTPS. Хост из ссылки временно добавьте в `.env` в строку `MEDIA_ALLOWED_HOSTS` (по умолчанию там только адреса Meta), затем перезапустите бота командой `docker compose up -d`.

```bash
docker compose exec app python -m app.simulate --url https://ХОСТ/файл.mp4 --text "есть в наличии?"
docker compose exec app python -m app.report
```

В чате менеджеров должно появиться сообщение со ссылкой на ролик и брифом. Карточка в этом тесте не найдётся, потому что клиент выдуманный. После проверки верните `MEDIA_ALLOWED_HOSTS` как было.

## Шаг 4. Приложение Meta

Названия кнопок в кабинете Meta иногда меняются. Шаги сверены с документацией Meta в ноябре 2026 года.

1. На developers.facebook.com создайте приложение: сценарий «Other», тип «Business».
2. Добавьте продукт Instagram и нажмите «Set up». Появится раздел «API setup with Instagram login».
3. В этом разделе добавьте свой аккаунт Instagram и создайте токен доступа. Аккаунт должен быть открытым. Токен впишите в `.env` как `IG_ACCESS_TOKEN`.
4. В «App settings», «Basic» скопируйте «App secret» в `.env` как `META_APP_SECRET`.
5. Перезапустите бота: `docker compose up -d`.
6. В разделе вебхуков нажмите «Configure». Callback URL: `https://ВАШ_ДОМЕН/webhooks/instagram`. Verify token: значение `META_VERIFY_TOKEN`. Сохраните и включите поле `messages`.
7. Включите доставку для аккаунта:

   ```bash
   docker compose exec app python -m app.subscribe
   ```

   Во второй строке ответа должно быть `"success": true`. Эта команда не проверялась на настоящем Instagram. Если она вернёт ошибку, сохраните текст ошибки.
8. Переведите приложение в режим Live. Без этого Meta не присылает события.

Если в журнале бота появится «подпись вебхука не совпала», впишите в `META_APP_SECRET` через запятую два значения: секрет приложения и секрет Instagram из раздела «API setup with Instagram login».

## Шаг 5. Что видно в Битрикс24

В ленте лида или контакта появляется комментарий:

```
Клиент прислал рилс в Instagram
От: Анна К (@anna_k)
Смотреть ролик (24 с): https://reels.вашдомен.kz/m/.../video.mp4
Подпись автора: ...
Сообщение клиента: есть в наличии?

Бриф от ИИ (уверенность: средняя)
Товар: ...
Категория: ...
Признаки: ...
Что уточнить: ...
ИИ может ошибаться, сверяйте с роликом.
```

К комментарию приложены три кадра и сам ролик, если он не больше 15 МБ. В чат менеджеров уходит короткое уведомление со ссылкой на карточку.

## Шаг 6. Главная проверка

1. В `.env` поставьте `LOG_RAW_EVENTS=1` и перезапустите бота.
2. С личного аккаунта Instagram, у которого нет роли в приложении Meta, отправьте бизнес аккаунту: рилс, рилс с текстом, пост и обычное сообщение.
3. Убедитесь, что в Битрикс24 переписка приходит как раньше.
4. Посмотрите отчёт:

   ```bash
   docker compose exec app python -m app.report
   ```

Как читать отчёт:

| Что в отчёте | Что это значит |
|---|---|
| Событий от Meta: 0 | События не доходят. Проверьте режим Live и шаг 4.7. Затем повторите с аккаунта, у которого есть роль тестировщика в приложении. Если с ним события приходят, нужна проверка приложения в Meta (App Review) |
| тип `ig_reel`, статус `done` | Бот получает рилсы и скачивает их. Основная часть работает |
| тип «неподдерживаемое» | Meta прислала рилс без ссылки на видео. Сохраните `data/events.jsonl` для разбора |
| канал `standby` | Основным получателем сообщений Meta считает канал Битрикс24. Бот обрабатывает такие события так же |
| совпадение `igsid` | ID клиента совпал с записью в Битрикс24. Карточка находится надёжно |
| совпадение `name` | Карточка найдена по имени. Работает, но при полных тёзках бот уйдёт в чат |
| совпадение «нет» | Карточка не найдена, бриф ушёл в чат менеджеров. Сохраните строку «поиск в Битрикс24» из отчёта |
| медиа: хост не входит в MEDIA_ALLOWED_HOSTS | Meta отдала ролик с другого адреса. Добавьте этот хост в `.env` |

После проверки верните `LOG_RAW_EVENTS=0`: при значении 1 в файл `data/events.jsonl` пишется текст переписки клиентов.

## Настройки

Все настройки лежат в `.env`, описание каждой есть в `.env.example`. Самые полезные:

* `BRIEF_ENABLED=0` отключает бриф. Бот только сохраняет ролик и даёт ссылку, ключ Claude не нужен.
* `CATALOG_PATH=/data/catalog.txt` подключает каталог. Положите в папку `data` текстовый файл с названиями и артикулами, и в брифе появится строка «Похоже на позицию каталога». Файл больше 400 000 символов бот не использует и пишет об этом в брифе.
* `CLAUDE_MODEL` выбирает модель. По умолчанию `claude-opus-5-5`. Один ролик из 8 кадров занимает примерно 6 000 входных токенов.
* `CLAUDE_FALLBACKS=1` включает запасную модель на стороне API: если основная отклонит запрос по правилам безопасности, API сам повторит его на другой модели. Для моделей Haiku поставьте 0.
* `BITRIX_ATTACH_VIDEO_MAX_MB` задаёт предел размера ролика, который прикладывается файлом. Если Битрикс24 не примет файл, бот повторит запись без него и оставит ссылку.
* `MEDIA_RETENTION_DAYS` задаёт срок хранения роликов на сервере, по умолчанию 30 дней.

## Что важно знать

* Ссылка на ролик длинная и случайная, но открывается у любого, кто её получил. Входа по паролю нет.
* Рилсы из закрытых аккаунтов Instagram может не прислать совсем.
* Речь из ролика пока не расшифровывается. Бриф строится по кадрам, подписи автора и тексту клиента.
* Токен Instagram живёт 60 дней. Бот сам обновляет его раз в неделю и хранит в `data/ig_token.json`.
* Бот ничего не пишет клиенту. Он только читает входящие события.

## Обслуживание

```bash
docker compose logs -f app                       # журнал
docker compose exec app python -m app.report     # сводка по событиям и роликам
git pull && docker compose up -d --build         # обновление
```

Данные лежат в папке `data`: ролики и кадры в `media`, журнал событий в `events.jsonl`, учёт обработанного в `bot.db`.

## Разработка

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest
```

Для тестов нужен установленный `ffmpeg`.
