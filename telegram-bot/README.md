# Бот: копирование между группами и автопубликация по расписанию

Telegram-бот, который:

- **копирует новые сообщения** из группы-источника в группу-получатель: текст, фото, видео, альбомы, документы, голосовые, кружки, стикеры, опросы, геолокацию. Копия приходит от имени бота **без плашки «Переслано»**, с подписями и форматированием;
- **публикует посты по расписанию**: вы выбираете время первой публикации, интервал и сколько раз повторить;
- работает с группами, супергруппами и каналами.

Управление — в личке с ботом, только для администраторов из `ADMIN_IDS`.

## Что бот не умеет (ограничения Telegram)

- **Старую историю он не копирует.** Обычный бот видит только сообщения, пришедшие после того, как его добавили в группу.
- Если сообщение отредактировали или удалили в источнике, копия не меняется.
- Если в группе-источнике включён запрет копирования («Запретить копирование»), Telegram не даст боту копировать.
- В одну группу бот может отправлять примерно 20 сообщений в минуту. При большом потоке он ждёт столько, сколько скажет Telegram, поэтому копии могут приходить с задержкой.

## 1. Создайте бота

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и получите **токен**.
2. Чтобы бот видел все сообщения в группе-источнике: в @BotFather `/setprivacy` → выберите бота → **Disable**.
   Можно не отключать, а сделать бота **администратором** группы-источника.
   Если меняете privacy, когда бот уже в группе, удалите его из группы и добавьте снова: иначе Telegram не применит настройку.

## 2. Установка

Нужен Python 3.10 или новее.

```bash
cd telegram-bot
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
```

Заполните `.env`:

| Параметр    | Что писать |
|-------------|------------|
| `BOT_TOKEN` | токен от @BotFather |
| `ADMIN_IDS` | ваш Telegram ID (можно несколько через запятую) |
| `TIMEZONE`  | часовой пояс, в котором вы задаёте время, например `Europe/Moscow`, `Europe/Kyiv`, `Asia/Almaty` |
| `DB_PATH`   | файл базы, по умолчанию `bot.db` |

Как узнать свой ID: впишите в `ADMIN_IDS` любое число, запустите бота и напишите ему `/start` — он ответит «Ваш Telegram ID: …». Впишите это число и перезапустите бота.

## 3. Запуск

```bash
python -m bot
```

Бот публикует только пока запущен, поэтому держите его на сервере или VPS (пример для systemd ниже).
Если бот был выключен в момент публикации, после запуска он опубликует пост один раз и дальше пойдёт по расписанию: пропущенные слоты он не наверстывает пачкой.

## 4. Добавьте бота в группы

- Добавьте бота в обе группы **со своего аккаунта** (из `ADMIN_IDS`). Бот напишет вам в личку: «➕ Бот добавлен в …».
- Если бот уже состоял в группе раньше, напишите в группе `/id` со своего аккаунта, и он добавит её в список.
- **Каналы:** добавьте бота администратором. В канал-получатель — с правом публикации сообщений.
- Если бота добавит посторонний человек, группа в список не попадёт: бот только сообщит вам об этом.

`/chats` в личке показывает все группы, которые знает бот.

## 5. Копирование из группы в группу

1. `/route` → выберите **откуда** → выберите **куда**.
2. Бот проверит свои права и предупредит, если что-то мешает (например, privacy mode включён и бот не админ).
3. Готово: каждое новое сообщение из источника копируется в получатель.

`/routes` — список связок с кнопками «Выкл/Вкл» и «Удалить».
Одна группа может копироваться в несколько групп, и в одну группу могут сходиться несколько источников.

## 6. Автопубликация по расписанию

`/new` запускает мастер:

1. **Контент.** Пришлите или перешлите боту одно или несколько сообщений (можно альбом) и нажмите «✅ Готово». Пересланное из группы опубликуется как обычный пост, без «Переслано».
2. **Куда.** Выберите группу кнопкой.
3. **Когда первая публикация:**

   | Пишете              | Значит |
   |---------------------|--------|
   | `сейчас`            | сразу |
   | `18:30`             | сегодня в 18:30, а если это время уже прошло — завтра |
   | `28.10 18:30`       | 28 октября этого года (если дата уже прошла — следующего) |
   | `28.10.2026 18:30`  | точная дата |
   | `через 2ч`, `+30м`  | через 2 часа / 30 минут |

4. **Сколько раз опубликовать:** число от 1 до 1000. `1` — один раз, без повторов.
5. **Как часто повторять:** `30м`, `2ч`, `1д`, `1д 12ч`, `90 мин` (от 1 минуты до 365 дней).
6. Бот покажет сводку с датой первой и последней публикации. Нажмите «✅ Создать».

Пример: первая в `10:00`, `3` раза, каждые `1ч` → публикации в 10:00, 11:00 и 12:00.

`/posts` — активные расписания: когда следующая публикация, сколько выполнено, последняя ошибка. Кнопки:
- «🚀 сейчас» — опубликовать вне очереди (счётчик повторов не меняется);
- «❌ отменить» — остановить расписание.

Когда расписание закончится или публикация не удастся (например, бота удалили из группы), бот напишет вам в личку. Неудачная публикация расходует свой запуск. При временном сбое сети бот повторит попытку через минуту, и запуск не расходуется.

> ⚠️ Бот копирует пост из вашей лички с ним. **Не удаляйте эти сообщения**, пока расписание не закончится.

## Команды

| Команда   | Где      | Что делает |
|-----------|----------|------------|
| `/new`    | личка    | новый пост по расписанию |
| `/posts`  | личка    | активные расписания |
| `/route`  | личка    | новая связка копирования |
| `/routes` | личка    | список связок |
| `/chats`  | личка    | группы бота и их ID |
| `/cancel` | личка    | прервать мастер |
| `/help`   | личка    | справка |
| `/id`     | группа / канал | показать ID чата (админу — ещё и добавить группу в список) |

## Деплой на Railway (бесплатно, без своего сервера)

[Railway](https://railway.app) даёт $5 бесплатных кредитов в месяц — для бота этого хватает с запасом.

1. Зарегистрируйтесь на [railway.app](https://railway.app) через GitHub.
2. **New Project** → **Deploy from GitHub repo** → выберите репозиторий `bitchat`.
3. В настройках сервиса укажите **Root Directory**: `telegram-bot`.
4. Перейдите во вкладку **Variables** и добавьте:

   | Переменная  | Значение |
   |-------------|----------|
   | `BOT_TOKEN` | токен от @BotFather |
   | `ADMIN_IDS` | ваш Telegram ID |
   | `TIMEZONE`  | `Europe/Moscow` (или ваш) |

5. Railway автоматически соберёт Docker-образ и запустит бота. Логи — во вкладке **Deployments**.

Бот перезапускается автоматически при сбоях. При новом коммите в ветку Railway пересоберёт и перезапустит бота.

> ⚠️ База `bot.db` хранится внутри контейнера. При каждом деплое она пересоздаётся: связки и расписания нужно настроить заново. Для продакшена подключите внешнюю БД (например, Neon PostgreSQL) — но для начала SQLite достаточно.

## Постоянная работа на сервере (systemd)

`/etc/systemd/system/telegram-bot.service`:

```ini
[Unit]
Description=Telegram copy & schedule bot
After=network-online.target

[Service]
WorkingDirectory=/opt/telegram-bot
ExecStart=/opt/telegram-bot/.venv/bin/python -m bot
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now telegram-bot
journalctl -u telegram-bot -f     # логи
```

## Данные

Группы, связки и расписания хранятся в `bot.db`. Сохраняйте копию этого файла, если переносите бота.
Ответы в мастере `/new` бот держит в памяти, поэтому, если перезапустить бота посреди мастера, начните `/new` заново. Уже созданные расписания перезапуск переживают.
